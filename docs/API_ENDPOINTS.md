# Language Learning API — Endpoint Reference (v1.0.3)

> **Audience:** an AI coding assistant updating a client application that calls this backend.
> **Source of truth:** generated from the Spring Boot source on branch `1.0.3` (including uncommitted changes to `SubjectController` / `SubjectService`, and the fixed subject delete). Every request/response shape below was confirmed by calling the running app with curl on 2026-10-29.
> **See also:** `docs/QUIRKS.md` lists every known oddity in the backend, including ones that don't affect the client.

---

## 0. TL;DR — what a client must change when moving from v1.0.2 to v1.0.3

1. **Every path now starts with a language segment.** `/{language}/...` where `language` is `es` (Castilian Spanish) or `ca` (Catalan). Case-insensitive (`es`, `ES`, `Es` all work). Any other value → `400`.
   - Old: `/subject/getall` → New: `/es/subject/getall`
   - Old: `/vocab/create` → New: `/es/vocab/create`
   - Old: `/lesson/get/5` → New: `/es/lesson/get/5`
2. **Vocab fields were renamed** in every request and response:
   - `esp` → `term` (the word in the language being learned)
   - `eng` → `translation` (the English meaning)
3. **Subject objects now include `"language": "ES" | "CA"`** (uppercase) in full-subject responses.
4. **Data is separated by language.** Subjects created under `/es/...` do not appear under `/ca/...`, and vocab/lessons belong to a language through their subject. The client needs a way to track the "current language" and put it in every URL.
5. **Subject update body:** send only `{ "subjectName": "..." }`. Extra fields like `id` are accepted and ignored. Language cannot be changed.
6. **Deleting a subject also deletes its vocab and its lesson.** The client should remove them from any local state/cache when the delete returns `204`.

The route names, HTTP methods, and the other field names did not change.

## 1. Conventions

| Item | Value |
|---|---|
| Base URL (local) | `http://<host>:8080` (binds `0.0.0.0`, default port 8080) |
| Base URL (prod) | port from the `PORT` env var, default 8080 |
| Path prefix | `/{language}` where `language ∈ {es, ca}`, case-insensitive |
| Request body | JSON, header `Content-Type: application/json` |
| Auth | None |
| CORS | **Not configured** (no `@CrossOrigin` or `WebMvcConfigurer`). A browser client on a different origin will be blocked unless it goes through a proxy. |
| Validation | None. Missing or null fields are stored as `null` unless noted. |
| IDs | Numeric (`Long`), generated by the database |
| JSON key order | Alphabetical on entity responses. Don't rely on key order. |

### Language values
| URL segment | Meaning | Value in JSON responses |
|---|---|---|
| `es` | Castilian Spanish | `"ES"` |
| `ca` | Catalan | `"CA"` |

### Status codes
| Code | When |
|---|---|
| `200` | Successful GET / POST / PUT. Note: **create returns 200, not 201.** |
| `204` | Successful DELETE (empty body) |
| `400` | Invalid `{language}` segment, a non-numeric id in the path, or a body that isn't valid JSON |
| `404` | Resource not found (custom error body, see below) |
| `405` | Wrong HTTP method (e.g. POST to an `/update/` route) |
| `415` | Body sent without `Content-Type: application/json` |
| `500` | Server-side failure (e.g. missing required `subjectId`, duplicate lesson for a subject) |

### Error body shapes

**404 (custom, from `GlobalExceptionHandler`):**
```json
{ "status": 404, "message": "Subject not found with id: 2", "timestamp": "2026-10-29T18:03:13.157504869" }
```
`timestamp` here is server-local time **with no timezone offset**.

**400 / 405 / 500 (Spring Boot default):**
```json
{ "timestamp": "2026-10-29T17:03:13.171Z", "status": 400, "error": "Bad Request", "path": "/fr/subject/getall" }
```

> Parse errors by `status`, not by `message`. Several 404 messages name the wrong resource (see §6).

## 2. Data shapes

The API returns several different shapes for the same resource depending on the endpoint. **Pay attention to which shape each endpoint returns**, because id field names and the presence of `subjectId` / `createdAt` vary.

### 2.1 Subject shapes

**`Subject` (full)**: returned by `getall`, `get/{id}`, `update/{id}`
```json
{
  "id": 1,
  "language": "ES",
  "subjectName": "Food",
  "lesson": { "id": 1, "lessonTitle": "Fruit", "body": "text", "createdAt": "2026-10-29T17:03:12.998Z" },
  "vocabs": [ { "id": 1, "term": "manzana", "translation": "apple" } ]
}
```
- `lesson` is `null` when the subject has no lesson.
- `vocabs` is `[]` when empty.
- Nested lesson/vocab objects have **no** `subjectId` (it's implied by nesting).

**`SubjectSummary`**: returned by `getsubjectnames`
```json
{ "id": 1, "subjectName": "Food" }
```

**`ReadSubject`**: returned by `create`. ⚠️ Uses **`subjectId`**, not `id`.
```json
{ "subjectId": 1, "subjectName": "Food" }
```

### 2.2 Vocab shapes

**`Vocab`**: returned by `getall`, `create`, `update/{id}`. ⚠️ **No `subjectId`.**
```json
{ "id": 1, "term": "manzana", "translation": "apple" }
```

**`VocabSummary`**: returned by `get/{id}`; also the request body for `update/{id}`
```json
{ "id": 1, "subjectId": 1, "term": "manzana", "translation": "apple" }
```

### 2.3 Lesson shapes

**`Lesson`**: returned by `getbysubject`, `create`, `update/{id}`. ⚠️ **No `subjectId`.**
```json
{ "id": 1, "lessonTitle": "Fruit", "body": "text", "createdAt": "2026-10-29T17:03:12.998Z" }
```
`createdAt` is an ISO-8601 UTC string, set by the server when the lesson is created.

**`LessonSummary`**: returned by `get/{id}`; also the request body for `update/{id}`. ⚠️ **No `createdAt`.**
```json
{ "id": 1, "lessonTitle": "Fruit", "body": "text", "subjectId": 1 }
```

### 2.4 Relationships
```
Subject (has a language: ES | CA)
 ├── Vocab   — many per subject
 └── Lesson  — at most ONE per subject (DB unique constraint)
```
Vocab and lessons don't store a language of their own. They inherit it from their subject.

## 3. Subject endpoints — `/{language}/subject`

| Method | Path | Request body | Response |
|---|---|---|---|
| GET | `/{language}/subject/getsubjectnames` | — | `SubjectSummary[]` |
| GET | `/{language}/subject/getall` | — | `Subject[]` (full, with nested lesson + vocabs) |
| GET | `/{language}/subject/get/{id}` | — | `Subject` (full) |
| POST | `/{language}/subject/create` | `{ "subjectName": string }` | `ReadSubject` → `{ subjectId, subjectName }` |
| PUT | `/{language}/subject/update/{id}` | `{ "subjectName": string }` | `Subject` (full) |
| DELETE | `/{language}/subject/delete/{id}` | — | `204` |

**Notes**
- `getsubjectnames` / `getall` return only subjects in `{language}`. Empty list → `[]`.
- `get/{id}`, `update/{id}`, `delete/{id}` return `404 "Subject not found with id: X"` if the subject doesn't exist **or belongs to a different language**.
- `create` assigns the subject to the language in the URL.
- `create`: no validation. `{}` creates a subject with `subjectName: null`. Duplicate names are allowed.
- `update` changes only `subjectName`.
- `delete` **cascades**: it deletes all of the subject's vocab, then its lesson (if any), then the subject. Works whether or not the subject has a lesson. Returns `204`. Afterwards, `GET /lesson/get/{lessonId}` and `GET /vocab/get/{vocabId}` for the removed children return `404`.

## 4. Vocab endpoints — `/{language}/vocab`

| Method | Path | Request body | Response |
|---|---|---|---|
| GET | `/{language}/vocab/getall` | — | `Vocab[]` (flat, **no `subjectId`**) |
| GET | `/{language}/vocab/get/{id}` | — | `VocabSummary` (includes `subjectId`) |
| POST | `/{language}/vocab/create` | `{ "term": string, "translation": string, "subjectId": number }` | `Vocab` |
| PUT | `/{language}/vocab/update/{id}` | `{ "term": string, "translation": string, "subjectId": number }` | `Vocab` |
| DELETE | `/{language}/vocab/delete/{id}` | — | `204` |

**Notes**
- `getall` returns every vocab item across all subjects in the language, **without a subject reference**. To group vocab by subject, use `GET /{language}/subject/getall` (vocab nested under each subject) or `GET /{language}/subject/get/{id}`.
- `create`: `subjectId` is required and must refer to a subject **in the same language**. Otherwise → `404 "Vocab not found with id: <subjectId>"` (the message says "Vocab" but means the subject; it reads `id: null` when `subjectId` is missing).
- `update`: **`subjectId` is required.** Omitting it → `404 "Subject not found with id: null"`. Send the current `subjectId` to keep the item in its subject, or a different one (same language) to move it. `id` in the body is ignored; the path id is used.
- `get`, `update`, `delete` → `404` if the vocab doesn't exist or its subject belongs to another language. `get/{id}`'s 404 message says `"Subject not found with id: X"` even though it's the vocab that's missing.

## 5. Lesson endpoints — `/{language}/lesson`

| Method | Path | Request body | Response |
|---|---|---|---|
| GET | `/{language}/lesson/get/{id}` | — | `LessonSummary` (has `subjectId`, no `createdAt`) |
| GET | `/{language}/lesson/getbysubject/{subjectId}` | — | `Lesson` **or empty body** |
| POST | `/{language}/lesson/create` | `{ "lessonTitle": string, "body": string, "subjectId": number }` | `Lesson` |
| PUT | `/{language}/lesson/update/{id}` | `{ "lessonTitle": string, "body": string, "subjectId": number }` | `Lesson` |
| DELETE | `/{language}/lesson/delete/{id}` | — | `204` |

**Notes**
- `getbysubject/{subjectId}`:
  - Subject exists but has no lesson → **`200` with an empty body** (not `null`, not 404). Clients must check for an empty response before parsing JSON.
  - Subject doesn't exist → `404 "Subject not found with id: X"`.
  - Doesn't filter by language. It returns the lesson whatever `{language}` is in the URL.
- `create`:
  - **`subjectId` is required.** Omitting it → **`500`**. Unknown `subjectId` → `404 "Subject not found with id: X"`.
  - Only **one lesson per subject.** Creating a second lesson for the same subject → **`500`**. Check `subject.lesson` (or `getbysubject`) first, and use `update` if a lesson already exists.
  - Doesn't check that the subject matches `{language}`. The client should only pass subjects from the current language.
  - Any `createdAt` in the request is ignored. The server sets it.
- `update`:
  - **`subjectId` is required.** Omitting it → **`500`**. Pass the lesson's current `subjectId` (available from `GET /lesson/get/{id}`).
  - If `subjectId` doesn't exist → `404 "lesson not found with id: <lessonId>"` (misleading message).
  - `createdAt` is kept.
- `get`, `update`, `delete` → `404 "lesson not found with id: X"` if the lesson doesn't exist or its subject is in another language.

## 6. Gotchas checklist for client code

- [ ] Add a current-language value (`es` / `ca`) and prefix **every** request path with it.
- [ ] Rename `esp` → `term` and `eng` → `translation` in all vocab models, forms, and display code.
- [ ] Subject create response uses `subjectId`; everywhere else subjects use `id`.
- [ ] `Vocab` / `Lesson` responses from create/update/getall have no `subjectId`. Keep it client-side, or re-fetch via `get/{id}`.
- [ ] Vocab and lesson create **and** update all **require** `subjectId` in the body.
- [ ] `GET /lesson/getbysubject/{id}` can return `200` with an **empty body**.
- [ ] Only one lesson per subject. Second create → `500`.
- [ ] Create endpoints return `200`, not `201`.
- [ ] Deletes return `204` with no body. Don't call `.json()` on them.
- [ ] Don't show 404 `message` strings to users as-is. Several name the wrong resource.
- [ ] Deleting a subject also deletes its vocab and lesson. Clear them from client state.
- [ ] Always send `Content-Type: application/json` on POST/PUT (otherwise `415`).
- [ ] Browser clients need a same-origin proxy: the API sends no CORS headers.

## 7. Example requests

```bash
# List Spanish subjects (names only)
curl http://localhost:8080/es/subject/getsubjectnames

# Create a Catalan subject
curl -X POST http://localhost:8080/ca/subject/create \
  -H 'Content-Type: application/json' -d '{"subjectName":"Menjar"}'
# → {"subjectId":2,"subjectName":"Menjar"}

# Add vocab to Spanish subject 1
curl -X POST http://localhost:8080/es/vocab/create \
  -H 'Content-Type: application/json' \
  -d '{"term":"manzana","translation":"apple","subjectId":1}'
# → {"id":1,"term":"manzana","translation":"apple"}

# Update vocab (subjectId required)
curl -X PUT http://localhost:8080/es/vocab/update/1 \
  -H 'Content-Type: application/json' \
  -d '{"term":"pera","translation":"pear","subjectId":1}'

# Create the lesson for subject 1
curl -X POST http://localhost:8080/es/lesson/create \
  -H 'Content-Type: application/json' \
  -d '{"lessonTitle":"Fruit","body":"text","subjectId":1}'

# Delete vocab
curl -X DELETE http://localhost:8080/es/vocab/delete/1   # → 204
```
